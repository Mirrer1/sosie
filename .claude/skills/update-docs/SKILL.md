# 문서 갱신

## 1. 무엇이 바뀌었나 파악

- `git log --oneline`에서 마지막 `docs:` 커밋 이후 커밋들과 `git diff`로 이번 작업 범위를 확인한다
- 대화에서 정한 결정(왜 이렇게 했는지, 무엇을 검토하고 버렸는지)이 있으면 함께 반영한다

## 2. 문서별로 넣을 곳

| 바뀐 것                                         | 갱신할 곳                                                         |
| ----------------------------------------------- | ----------------------------------------------------------------- |
| 기능 구현 (항상)                                | `.claude/history.md` 맨 끝에 항목 추가                            |
| 사용자가 볼 수 있는 기능 범위, URL, 명령어 변경 | `CLAUDE.md`의 "현재 상태", "URL 구조", "자주 쓰는 명령어"         |
| 영역별 설계 결정 (정책, 동작 원칙, 왜 안 만듦)  | `.claude/rules/product/`의 해당 영역 파일                         |
| 코딩 규칙이 새로 생기거나 바뀜                  | `.claude/rules/code/`의 해당 파일                                 |
| 새 env 키                                       | README "환경 변수" 절 (`.env.example`은 없음)                     |
| 평가자에게 보이는 기능, 기술 스택, 라우트 변경  | README "주요 기능", "라우트", "기술 스택", "설계 노트"            |
| 새 영역이 생겨 기존 rules에 안 맞음             | `product/`에 새 파일 + `paths` 지정, `CLAUDE.md` 규칙 표에 한 줄  |

원칙:

- `CLAUDE.md`와 `paths` 없는 rules는 매 대화 읽히므로 짧게 유지한다. `CLAUDE.md`는 100줄 안쪽
- rules엔 "무엇을, 왜"만 쓰고 코드로 확인되는 세부(스키마 컬럼, Tool 스키마 필드, 검색어 목록, 사전 키)는 쓰지 않는다. 기준 파일(`src/types/`, `src/lib/catalog/schema.sql`)을 가리킨다
- 같은 내용을 여러 rules 파일에 쓰지 않는다. 한 파일에 두고 다른 파일에선 파일명으로 가리킨다
- 기존 결정을 뒤집었으면 옛 문장을 지우고 새 결정과 이유로 교체한다. 버린 대안이 의미 있으면 "기각한 대안"으로 한 줄 남긴다
- `paths` glob이 실제 파일과 맞는지 확인한다. Next 라우트 그룹처럼 괄호가 있는 폴더는 `src/app/*group*/**`처럼 쓴다
- 코드 이름(함수, 파일, 숫자 값)을 적었다면 실제 코드에 있는지 grep으로 확인한다

## 3. history.md 항목 형식

- `**굵은 제목.**`으로 시작하는 한 문단 (한 작업 묶음 = 한 항목, 최신이 맨 뒤)
- 무엇을 했나 → 어떻게(핵심 파일과 함수는 백틱) → 왜 그렇게 했나 순서
- 사용자 입장의 동작 설명을 먼저 쓴다
- 부수 작업은 문단 끝에 `곁가지:`로 붙인다

예:

```md
**구매 직링크.** 카드와 가격비교 판매처 행의 링크를 `/go/[id]`로 통일하고 첫 클릭 때 `resolveProductUrl`이 SerpApi 판매처 조회로 직링크를 받아 `direct_url`에 저장한 뒤 302 이동. 판매처 조회가 상품당 크레딧 1회라 수집 시점이 아니라 클릭 시점으로 미뤘다. 곁가지: robots에서 `/go/` 차단.
```

## 4. 마무리

- `npx prettier --write`로 수정한 md 파일을 정리한다
- 커밋은 사용자가 요청할 때만 `docs: 문서 갱신` 형태로 한다
