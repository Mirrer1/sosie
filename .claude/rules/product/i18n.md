# 다국어와 가격 현지화 설계 결정

지원 언어 목록의 기준은 `src/i18n/languages.ts`, 언어별 통화는 `src/i18n/currency.ts`다.

## 다국어

- 라이브러리 없이 Context + 언어별 사전 + localStorage(`sosie:language`)로 클라이언트에서 전환한다. URL 경로(`/en`)는 쓰지 않는다
- 단일 페이지 채팅 앱이라 콘텐츠 대부분이 AI 실시간 생성이고 정적 색인 가치가 낮다. `next-intl`은 `app/[locale]` 폴더 재구성이 필요해 비용 대비 실익이 없었다
- 첫 방문은 저장값이 없으면 브라우저 언어 앞 두 글자로 추정하고 지원하지 않으면 한국어
- 사전 타입은 `ko`만 완전한 원본으로 강제하고 나머지 언어는 부분 허용한다. 빠진 키는 `ko`로 대체돼 번역 누락이 빌드를 막지 않으면서 화면도 안 깨진다. 새 키를 추가하면 가능한 한 모든 언어에 채운다
- AI 답변 언어는 선택 언어를 매 요청 `body`에 실어 시스템 프롬프트에 최우선 지시로 붙인다
- 상품명, 브랜드, 판매처는 실제 커머스 데이터라 번역하지 않는다. 검색과 링크 정합성을 지키기 위함. 스타일과 프리셋 브랜드는 저장값을 한국어로 두고 표시 라벨만 번역한다
- 언어를 바꿔도 이미 생성된 대화는 생성 시점 언어 그대로 둔다. 재번역은 비용과 원문 훼손 대비 실익이 없다
- 한계: Context 기반이라 서버 컴포넌트는 번역하지 않고 정적 메타데이터는 한국어 기본이다. 한국어 외 사전은 기계 생성이라 뉘앙스를 다듬을 여지가 있다

## 가격 근사 환산

- 원화를 주로 두고 선택 언어 통화의 근사치를 괄호로 곁들인다 (`50,000원 (≈ $38)`). 실제 결제는 한국 쇼핑몰의 원화라 환산가로 대체하면 보이는 값과 결제 값이 달라진다
- 한국어는 기준 통화라 환산을 표시하지 않는다. 언어와 통화는 일대일이 아니지만 근사치라 언어별 대표 통화로 충분하다
- 할인가처럼 보이지 않게 세로 배치, 색 강조, 취소선을 쓰지 않고 같은 줄에 흐린 작은 글씨로 둔다
- 환율은 `open.er-api.com`(무키, 무료)을 하루 한 번 조회해 localStorage `sosie:rates`에 날짜와 함께 캐시한다. 실패하면 조용히 원화만 표시한다
