# 채팅 화면 설계 결정

## 로그인 없음, 사용자 데이터는 localStorage

- 로그인과 가입 없이 바로 쓴다. 평가자가 링크를 열자마자 시연할 수 있게 진입 마찰을 없애고 인증 구축 시간을 AI 품질에 쓰기 위함
- 대화, 프로필, 찜, 언어, 환율 캐시는 전부 브라우저 localStorage에 둔다. DB는 상품 카탈로그에만 쓴다(`catalog.md`)
- 한계: 다른 기기와 브라우저에서 이어지지 않고 운영 분석이 없다. 실서비스 단계라면 인증과 서버 저장을 도입한다

## 대화 히스토리

- `useChat`의 `messages`를 localStorage `sosie:messages`에 자동 저장하고 마운트 시 복원한다. 복원 전에는 스켈레톤을 보여 빈 화면 깜빡임을 막는다(`isHydrated`)
- Tool 오류가 난 응답과 그 직전 사용자 메시지는 저장과 복원에서 뺀다(`stripFailedExchanges`). 새로고침 후 실패 카드가 남지 않게 하기 위함
- 저장 실패(용량 초과)는 조용히 무시한다. base64 이미지가 포함된 대화는 용량을 빨리 채운다
- 탭 간 동기화와 여러 대화 세션은 지원하지 않는다

## 헤더와 채팅 사이 통신

`Header`와 `ChatRoot`는 트리가 분리돼 prop drilling 대신 window 커스텀 이벤트를 쓴다.

| 이벤트              | 방향             | 용도                                         |
| ------------------- | ---------------- | -------------------------------------------- |
| `sosie:clear-chat`  | 헤더 → 채팅      | 확인 모달 후 대화 초기화                     |
| `sosie:open-profile` | 헤더 → 채팅      | 프로필 마법사 다시 열기                      |
| `sosie:chat-busy`   | 채팅 → 헤더      | AI 응답 중 대화 초기화와 프로필 버튼 잠금    |
| `sosie:ask`         | 상품 미리보기 → 채팅, 찜 목록 | 미리보기에서 보낸 질문 전송, 찜 목록 닫기 |
| `sosie:profile-changed` | 상품 미리보기 → 채팅 | 추천 이유 링크로 연 마법사에서 저장한 프로필을 다시 읽기 |

응답 중 버튼을 잠그는 이유는 스트리밍 도중 대화가 지워지거나 프로필이 바뀌어 응답과 상태가 어긋나는 것을 막기 위함이다.

## 입력

- 이미지는 파일 선택, 드래그앤드롭, 클립보드 붙여넣기 3가지로 받는다. JPEG, PNG, WebP 5MB 이하만 허용하고 기준은 `src/utils/image.ts`
- 이미지는 base64 data URL file part로 보내고 확대 라이트박스로 다시 볼 수 있다
- 웰컴 화면 예시 칩과 빈 결과 추천 칩은 누르면 바로 전송한다

## 표시

- Tool 진행 단계를 아이콘과 문구로 노출한다(진행 중 회전, 완료 체크, 실패 경고). AI 답변 전에는 "생각 중" 표시. 에이전트가 무엇을 하는지 보이는 것이 평가 포인트다
- 검색 결과가 비면 추천 검색어 칩(`ChatEmptyResult`), Tool이 실패하면 다시 시도 카드(`ChatToolError`)를 보여준다
- 스마트 자동 스크롤: 사용자가 맨 아래에서 80px 이내일 때만 새 메시지에 따라 내려가고, 위로 올려 읽는 중이면 멈추고 아래로 가기 버튼을 띄운다
- assistant 답변만 마크다운으로 렌더링하고 사용자 메시지는 원문 그대로 보여준다
