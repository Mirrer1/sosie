# 상품 카드와 찜 설계 결정

구매 링크 이동 방식과 가격비교를 없앤 이유는 `catalog.md`에 있고 여기엔 화면 동작만 둔다.

## 카드 클릭 = 상품 미리보기

- 카드를 누르면 `ProductPreviewDialog`가 열린다. 바로 판매처로 보내면 AI가 붙인 태그와 개인화가 화면에 드러나지 않아서, 구매 전에 "왜 나에게 추천됐는지"를 한 번 보여주는 단계를 뒀다
- 구성: 큰 이미지, 브랜드와 이름과 가격, AI 태그(스타일은 강조, 세부 품목과 색상과 소재와 성별은 보조. 세부 품목과 색상과 소재는 수집 때 한국어로만 태깅돼 번역본이 없어서 한국어가 아닌 언어에선 숨기고 번역되는 스타일과 성별만 보여 칩 언어가 섞이지 않게 한다), 추천 이유, "구매하러 가기" 구매 링크, 찜 토글, "이런 스타일 더 찾아줘", 비슷한 상품 그리드
- 서비스 UI 문구에는 무신사 같은 판매처나 외부 브랜드 이름을 넣지 않는다. 구매 버튼은 판매처와 무관하게 "구매하러 가기"로 통일한다. 판매처명이 버튼 문구에 들어가면 서비스가 특정 몰의 안내 페이지처럼 보이기 때문이다. 상품 데이터로 보여주는 브랜드명은 예외
- **추천 이유**(`buildMatchReasons`)는 프로필 이유(스타일, 예산 안, 브랜드, 정확히 같은 성별)를 먼저 채우고 남는 자리에 찜 이유(같은 브랜드, 같은 스타일, 예산이 없을 때 비슷한 가격대)를 채워 최대 3개. 프로필은 사용자가 직접 밝힌 취향이라 찜보다 강한 근거로 앞세운다. 프로필과 겹치는 브랜드나 스타일은 찜 이유로 중복 표시하지 않는다. 3개로 자르는 이유는 모달 크기 고정 원칙 때문이다. 이유 칸만 스크롤하면 모달 안에 스크롤이 겹쳐 조작이 어색하고, 칸을 늘리면 상품마다 모달 크기가 달라져서, 우선순위가 높은 3개만 보여주는 쪽을 택했다. 서버 검색이 실제로 가산한 기준과 같은 신호라 설명과 결과가 어긋나지 않는다. 프로필은 렌더할 때마다 localStorage에서 바로 읽고 찜은 Context 값을 써서, 프로필 저장이나 찜 추가 직후 연 미리보기에도 즉시 반영된다. 보고 있는 상품 자신은 찜 신호에서 빼서 "찜했으니 찜한 브랜드" 같은 자기 참조 이유가 나오지 않게 한다
- **추천 이유 링크**: 이유 문장에서 근거가 되는 부분("선호 스타일 캐주얼", "찜한 상품")만 점선 밑줄 버튼으로 둔다. 사전 문구의 대괄호 구간이 링크다(`splitReasonText`). 프로필 이유는 프로필 마법사를 해당 단계(스타일 1, 브랜드 2, 성별 3, 예산 4)로 열고, 찜 이유는 그 이유가 된 찜 상품만 모은 모달(`ProductReasonFavoritesDialog`, `favoritesForReason`)을 연다. 둘 다 미리보기를 닫지 않고 그 위에 겹쳐 띄운다. 닫고 카드를 다시 눌러 미리보기를 여는 왕복을 없애기 위함이다. 겹친 모달은 미리보기 안에 렌더링해 중첩 다이얼로그로 동작하게 해서 겹친 모달을 조작해도 미리보기가 바깥 클릭으로 닫히지 않는다. Base UI는 중첩 다이얼로그의 배경 오버레이를 기본으로 그리지 않아 겹친 모달 뒤 미리보기가 흐려지지 않았으므로, 공용 `DialogOverlay`의 `forceRender`를 기본 true로 두어 중첩에서도 배경 흐림이 같게 보이게 했다. 프로필을 저장하면 `sosie:profile-changed` 이벤트로 채팅의 프로필 상태도 갱신하고, 근거 찜 상품을 누르면 찜 모달을 닫고 미리보기를 그 상품으로 바꾼다
- **이런 스타일 더 찾아줘**는 `sosie:ask` window 이벤트로 채팅에 메시지를 보내고 미리보기와 찜 목록을 닫는다. AI 응답 중에는 비활성
- **비슷한 상품**은 `/api/products/[id]/similar`로 같은 카테고리와 성별에서(기준 상품이 무신사면 무신사 상품만, 그 외엔 지원 판매처 전체) 세부 품목 일치, 스타일 겹침, 가격 차이 순으로 8개. DB 조회라 크레딧이 들지 않고, 누르면 미리보기가 그 상품으로 바뀐다. 같은 상품은 캐시한다
- **크기 고정, 스크롤 없음**: 이미지 로드나 비슷한 상품 조회가 끝날 때, 그리고 상품이 바뀔 때 모달과 안쪽 내용 크기가 변하거나 스크롤이 생기지 않게 모든 영역 높이를 고정한다. 내용 양이 달라도 같은 크기로 보이는 것이 목표다
  - 이미지는 고정 크기 정사각형 칸에 `object-cover`로 채우고 로드 후 페이드인
  - 상품명은 2줄, 브랜드와 가격과 추천 이유 각 줄은 1줄에서 말줄임, 태그는 2줄 높이를 넘으면 잘라낸다
  - 추천 이유 칸은 이유가 없어도 안내 문구로 같은 높이를 채운다
  - 비슷한 상품은 가로 스크롤 대신 PC 5칸, 모바일 3칸 그리드로 보여주고 로딩 스켈레톤, 결과, 빈 칸, 결과 없음 안내가 모두 같은 높이를 차지한다
  - 2026-09-15 헤드리스 측정: 긴 상품명과 짧은 상품명 모두 PC 604px, 모바일 629px로 같고 내용 높이가 모달 높이와 같아 스크롤 없음
- 모바일은 작은 이미지 옆에 브랜드와 이름과 가격, 그 아래 태그와 추천 이유와 버튼을 두고, PC는 큰 이미지 왼쪽과 정보 오른쪽 2단. "이런 스타일 더 찾아줘"는 비슷한 상품 제목 옆에 둬서 맥락을 맞추고 세로 공간을 아꼈다. 닫기 버튼은 이미지 위에서도 보이게 반투명 배경을 둔다
- 가격이 매일 수집 기준이라 판매처와 다를 수 있다는 안내를 구매 버튼 아래에 둔다
- 예전엔 카드 클릭이 가격비교 모달이었다가 판매처 직행이었고, 판매처가 항상 1곳이라 모달을 없앤 뒤 정보가 부족해 미리보기로 바꿨다

## 찜

- `FavoritesProvider` Context + localStorage `sosie:favorites`. 헤더 개수 뱃지와 카드 하트가 동시에 반응해야 해서 전역 Context를 택했다
- 카드 위 하트 버튼은 `stopPropagation`으로 카드 클릭(미리보기)과 분리한다
- 찜 목록 모달은 `ProductGrid`를 재사용해 미리보기까지 그대로 동작한다. 미리보기가 열린 동안 뒤 찜 목록이 비쳐 지저분해서 찜 모달을 `opacity-0`으로 숨긴다(`onPreviewOpenChange`)
- **찜 취향 신호**(`summarizeFavorites`)를 매 요청에 싣는다. 자주 찜한 브랜드 상위 3개("무신사"와 "브랜드 미상" 제외), 스타일 상위 2개, 가격대. 찜 1개만 해도 바로 체감되도록 찜이 2개 이하면 한 번 나온 스타일도 쓰고 찜이 3개 이상이면 두 번 이상 나온 스타일만 쓴다(우연 제거). 가격대는 찜 가격의 하위 25%~상위 25%, 찜이 하나면 그 가격 앞뒤 30%
- 찜은 프로필보다 한 단계 약한 신호로 쓴다. 검색에서의 쓰임은 `catalog.md`
- 찜은 저장 당시 상품 객체를 그대로 보관한다. 네이버 시절 찜은 태그가 없어 신호에서 빠지고 링크는 옛 네이버 주소다
