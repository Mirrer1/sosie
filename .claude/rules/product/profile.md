# 프로필 설계 결정

프로필 스키마와 옵션 상수(스타일, 인기 브랜드, 사이즈, 예산 범위)의 기준은 `src/types/profile.ts`다. 여기엔 왜 그렇게 만들었는지만 둔다.

## 왜 프로필인가

첫 버전("닮은 옷 다 모아드려요" + 큐레이션 5개)은 매 대화가 단발성 검색이라 "AI 검색 wrapper" 인상이 강했다. 그래서 "옷 사고 싶을 때 같이 골라주는 스타일리스트"로 피벗하고, 사용자 컨텍스트를 누적해 매 검색에 곱하는 **프로필 → 검색 → 답변 → 프로필 갱신** 닫힌 루프를 핵심으로 삼았다. 답변이 "캐주얼 좋아하시니까"처럼 컨텍스트를 인용하는 것이 에이전트다움을 보여주는 지점이다.

## 입력

- 첫 진입 시 4단계 마법사(스타일 → 브랜드 → 성별과 사이즈 → 예산)를 띄우고 모든 항목은 선택이다. 프로필을 매번 묻는 방식은 마찰이 커서 버렸다
- **성별**은 남성과 여성 중 하나를 고르거나 비워둔다. 비우면 남녀 상품을 모두 보여준다. 검색이 AI 태그 성별로 필터하는데 기준이 없으면 남녀 상품이 섞여 추천이 흐려져서 추가했다. 단계를 늘리지 않으려고 신체 정보인 사이즈와 한 단계에 묶었다
  - 검색 반영: 반대 성별 상품은 빼고 공용은 포함하되 정확히 같은 성별을 가산점으로 앞세운다. 이번 요청에 "남자", "여자"가 있으면 프로필보다 우선
  - 측정(반팔티, 요청당 6개 × 8회): 프로필 남성이면 남성 100%, 여성이면 여성 79%와 공용 21%
- 닫기만 해도 빈 프로필 `{}`을 저장해 다시 뜨지 않게 한다. 헤더 프로필 버튼은 `sosie:open-profile` window 이벤트로 마법사를 다시 열고, 상품 미리보기의 추천 이유 링크는 `initialStep`으로 해당 단계부터 연다
- 브랜드는 인기 브랜드 칩과 자유 입력을 함께 받는다
- 기본 스타일에 클래식과 고프코어를 넣고 포멀은 뺐다. 옛 저장값 호환을 위해 라벨 매핑(`profileLabels.ts`)에는 포멀과 나이키가 남아 있다
- 저장값은 한국어 원문이고 화면 라벨만 사전으로 번역한다

## 예산

- 0~100만 원을 5만 단위 듀얼 썸 슬라이더로 받는다. 예전 4개 프리셋 칩은 세밀한 범위를 못 담고 AI가 자유 금액을 가장 가까운 프리셋으로 반올림해 의도가 사라졌다
- 하한 0은 `min` 생략, 상한 끝(100만)은 `max` 생략으로 "이상"을 뜻한다
- 스키마(`budget: { min?, max? }`)와 검색 인자는 원래 자유 범위라 프리셋 제거가 검색 품질에 영향을 주지 않았다. 극단값은 검색의 예산 소프트 필터가 빈 결과를 막는다
- 표시는 원화 금액과 근사 환산을 두 줄로 나눈다. 일본어처럼 긴 통화 표기가 옆으로 늘어지지 않게 하기 위함

## 대화 중 학습 (`updateProfile`)

- 서버 Tool은 변경 필드와 `mode`, `reason`을 되돌려주기만 한다. 서버는 localStorage에 접근할 수 없어 저장은 클라이언트 몫이다
- 결과를 바로 적용하지 않고 컴포저 위 확인 카드(`ProfileUpdatePrompt`)에서 사용자가 반영이나 나중에를 고른다. 즉시 반영은 "내가 모르게 프로필이 바뀐다"는 불안을 줬다
- 성별은 "남성", "여성", "전체"로 받고 "전체"는 성별 설정 해제다. 프로필 스키마에는 남성과 여성만 두고 해제는 필드를 지워서 표현한다
- `merge`는 배열 합집합, 성별과 사이즈와 예산은 새 값으로 교체한다. 예산은 하나의 범위라 필드별로 섞지 않는다. `replace`는 보낸 필드를 통째로 바꿔 배열 비우기가 가능하다
- 복원한 과거 대화의 `toolCallId`는 이미 처리한 것으로 시드해 카드가 다시 뜨지 않게 한다. `updateProfile`의 Tool 진행 표시는 확인 카드와 겹쳐 숨긴다
