# 공통 규칙

> 모든 작업에 적용. 파일 종류별 코드 규칙은 `code/`, 영역별 설계 결정은 `product/`의 파일이 해당 파일을 다룰 때 자동 적용된다.

## Next.js 16 주의

App Router 기반이지만 학습 데이터의 Next.js와 API, 컨벤션, 파일 구조가 다를 수 있다. Next 관련 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 해당 가이드를 확인한다. Turbopack이 기본 dev와 build 엔진이고 Tailwind는 v4라 `tailwind.config.js` 없이 `globals.css`에서 설정한다.

## 협업 방식

1. 코드 변경 전 설명하고 승인받는다. 임의로 결정하지 않는다
2. 단계별로 진행한다. 한 번에 여러 기능을 섞지 않는다
3. 짧고 핵심만 설명한다
4. 외부 계정 가입, 배포, 환경 변수 등록은 사용자가 직접 한다. 명령어와 순서만 안내한다
5. 막히면 질문부터 한다

## 작업 흐름 (커밋 1단위)

1. 기능 구현
2. 테스트 방법 안내 (Vitest 또는 화면 확인 명령어)
3. 화면 테스트 항목 안내
4. 사용자가 결과를 알려준다
5. 문제가 있으면 수정하고 없으면 커밋명을 추천한다

## 주석 스타일

| 위치                         | 주석               |
| ---------------------------- | ------------------ |
| 인터페이스와 타입 필드       | 필드 뒤 `// 한 줄` |
| 컴포넌트, 유틸, 콜백, useEffect | 위에 `// 한 줄`    |
| state, 일반 변수, JSX        | 달지 않음          |

- 한 문장으로 사실 위주로 담백하게 쓴다. 수식어와 비유는 쓰지 않는다
- 두 절을 콤마로 잇지 않는다. `~고`, `~며`, `~서`로 한 문장으로 묶거나 핵심만 남긴다
- 한글 단어를 나열할 때 `·`, `/`, `+`를 쓰지 않는다. 포괄 단어 하나로 묶고, 없으면 `~와`/`~과`, 그래도 없으면 콤마
- `~지 않음` 같은 부정형 대신 긍정 명사형으로 쓴다 (예: "캐시에 남기지 않음" → "캐시에서 제외")
- 영어 코드 식별자와 약어는 그대로 둔다
- 괄호 부연설명, 특수문자 장식(`── ──`, `=`), 다른 코드와의 관계나 비교 언급, JSDoc(`/** */`)은 쓰지 않는다

## 파일, 폴더 명명

- 컴포넌트 `PascalCase.tsx`, 훅 `useXxx.ts`, 유틸과 타입 `camelCase.ts`
- Next.js 특수 파일은 소문자 고정 (`page.tsx`, `layout.tsx`, `route.ts`)
- 폴더는 한 단어면 소문자, 합성 단어면 `camelCase`
- 페이지나 기능에 종속된 컴포넌트는 스코프 접두어를 붙인다 (채팅 `ChatMessage`, 상품 `ProductCard`). 공용과 shadcn 컴포넌트는 접두어 없음

## 위치

- 컴포넌트는 기능별 폴더 `src/components/{chat,product,profile,layout}`, shadcn은 `src/components/ui/`. 단일 페이지 앱이라 `_components/`는 쓰지 않는다
- Context 프로바이더는 `src/providers/`에 모으고 `AppProviders`에서 조립한다. 도메인 종속이라도 조립 지점을 한곳으로 둔다
- 다국어 리소스는 `src/i18n/`, 순수 함수는 `src/utils/`, 외부 연동과 Tool은 `src/lib/`, 상품 수집과 DB 로직은 `src/lib/catalog/`, 로컬 실행 스크립트는 `scripts/`
- 공유 타입은 `src/types/` 도메인별 파일, Props와 작은 로컬 타입은 그 파일 안. 2~3곳 이상 반복되면 `types/`로 올린다

## 상수

- 한 파일 안에서 3곳 이상 쓰면 파일 상단 대문자 상수로 분리하고 1~2곳이면 인라인
- 환경별로 다른 값은 env로 둔다
- 별도 `constants/` 폴더는 만들지 않는다

## 환경 변수

- env 파일은 gitignore. 로컬은 `.env.local`, 배포 값은 Vercel 대시보드에 같은 이름으로 등록한다
- 키 목록과 발급처의 기준은 README "환경 변수" 절이다. `.env.example`은 없다
- 새 키가 생기면 README 환경 변수 절에 추가한다

## 커밋과 Git

- 브랜치는 `main` 하나, 이슈와 PR 없음
- 커밋 메시지는 prefix(`feat:`, `fix:`, `refactor:`, `chore:`, `test:`, `style:`, `docs:`) + 한 개념으로 뭉뚱그린 한 구절
- 여러 변경은 나열하지 말고 상위 개념 하나로 일반화한다
- `및`, `/`, `~와`, `~과` 같은 연결자와 `변경`, `수정` 같은 군더더기, `을`/`를` 조사는 뺀다
- 예: `fix: 구경하기 버튼 로그인으로 연결`, `feat: 찜 기반 브랜드 개인화`
- 커밋은 사용자가 요청할 때만 한다
